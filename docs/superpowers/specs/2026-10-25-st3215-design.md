# ST3215 バスサーボのドライバと単体検証 設計書（2026-10-25）

## 1. 背景と目的

gamma の装填機構（トリガーホイール式。設計メモ `Rabbits/docs/superpowers/specs/2026-07-26-bb-feeder-trigger-wheel-design.md`）は Feetech ST3215（Waveshare 版、7.4V）をステップモードで回す。設計メモ 5.1 に「試作時のサーボ単体検証 4 項目」が宿題として残っている:

1. ステップモード中の現在位置レジスタの多回転挙動（±32768 のオーバーフローで巻き戻るか）
2. 到達判定の方法（ステップモードでの Moving / 位置読みの振る舞い）
3. 171 カウント（15°）ステップの所要時間（7.4V・無負荷。100 ms 周期が成り立つか）
4. ジャム復旧の負方向相対ステップ

ソフトは何も無い。rabcl に ST3215 のプロトコルとドライバ、rabcl_esp32 に半二重 UART、gamma ファームに試験用の動作モードを作り、gamma_turret 基板の SRV1（1 kΩ 合流の半二重バス）で上の 4 項目を測る。装填の本実装（ホイールの状態機械、ジャム復旧、PC からの `load` モードとの接続）は次の設計で、ここでは**ドライバと検証ツールまで**。

非目標: 装填の状態機械、ジャム検知・復旧の自動化、複数サーボの同期書き込み、EEPROM の ID / ボーレート変更（出荷時 ID 1、1 Mbps のまま使う）。

## 2. 電気と配線（確定事項）

- gamma_turret 基板 SRV1（XH 3P: 7.4V / Data / GND）。P4 の UART1、TX = G8（1 kΩ 直列で Data に合流）、RX = G10（1 kΩ 直列で Data 直結）。Data は 10 kΩ で 3.3V にプルアップ。送信は RX にそのまま返る（エコー）ので**ファームで送信バイト数分を読み捨てる**（基板設計メモ 4-3、7 章）。
- 7.4V は今回は安定化電源（電流制限 2 A）を外部 DCDC の戻り側 XT30 に入れる。24V は無し（P4 は USB 給電、バスは 3.3V 系）。
- サーボは出荷時のまま: ID 1、1 Mbps。無負荷（ホーンに何も付けない）。

## 3. プロトコル（Waveshare 配布の SCServo ライブラリ SCS.cpp / SMS_STS.cpp / INST.h から確認、2026-10-25）

- 命令パケット: `FF FF ID LEN INST [ADDR DATA…] CHK`。LEN = パラメータ数 + 2（READ なら ADDR と長さの 2 バイトで LEN = 4、WRITE n バイトで LEN = n + 3、PING は LEN = 2）。CHK = ~(ID + LEN + INST + ADDR + DATA…) の下位 8 bit。
- 命令: PING 0x01、READ 0x02、WRITE 0x03、REG_WRITE 0x04、ACTION 0x05、SYNC_READ 0x82、SYNC_WRITE 0x83。
- 応答（状態パケット）: `FF FF ID LEN ERR [DATA…] CHK`。WRITE / PING の応答は LEN = 2（ERR と CHK）。READ の応答は DATA が n バイトで LEN = n + 2。CHK = ~(ID + LEN + ERR + DATA…)。ヘッダの前にごみが混ざることがあるので FF FF を探してから読む（ライブラリは 10 バイトまで読み飛ばす）。
- 16 bit は**リトルエンディアン**（STS 系。SCS 系はビッグエンディアン）。
- 負の値は**符号付き絶対値**: bit15 が符号、下位 15 bit が絶対値（例: −100 = 0x8064）。目標位置（ステップモードの相対量）、目標速度、現在位置 / 速度 / 電流の読みも同じ。**現在負荷（60-61）だけは bit10 が符号**（ライブラリ `ReadLoad` の `Load & (1<<10)`。下位 10 bit が絶対値）。
- レジスタ（10 進）: MODEL 3-4、ID 5、BAUD 6、MIN_ANGLE 9-10、MAX_ANGLE 11-12、OFS 31-32、MODE 33（0 位置、1 定速、2 PWM、3 ステップ）、TORQUE_ENABLE 40、ACC 41、GOAL_POSITION 42-43、GOAL_TIME 44-45、GOAL_SPEED 46-47、TORQUE_LIMIT 48-49、LOCK 55（0 = EEPROM 書き込み可、1 = ロック）、PRESENT_POSITION 56-57、PRESENT_SPEED 58-59、PRESENT_LOAD 60-61、PRESENT_VOLTAGE 62、PRESENT_TEMPERATURE 63、MOVING 66、PRESENT_CURRENT 69-70。ACC〜GOAL_SPEED（41〜47）の 7 バイトを 1 回の WRITE で書くのがライブラリの `WritePosEx`。
- MODE（33）は EEPROM 側。書く前に LOCK = 0、書いた後 LOCK = 1。
- 分解能 4096 カウント / 回転、位置の範囲 0〜4095（位置モード）。ステップモードは相対カウント指令で ±7 回転まで、多回転カウントは電源断で消える（Waveshare wiki）。

rabcl（PC テスト可）        rabcl_esp32（ESP32）             gamma_turret_fw

### 4.1 rabcl `component/st3215.hpp`（機体の値は書かない）

```cpp
namespace rabcl {
class St3215Protocol
{
public:
  static constexpr uint8_t INST_PING = 0x01, INST_READ = 0x02, INST_WRITE = 0x03, INST_REG_WRITE = 0x04,
    INST_ACTION = 0x05, INST_SYNC_WRITE = 0x83;
  static constexpr uint8_t REG_MODEL = 3, REG_ID = 5, REG_BAUD = 6, REG_MIN_ANGLE = 9, REG_MAX_ANGLE = 11,
    REG_OFS = 31, REG_MODE = 33, REG_TORQUE_ENABLE = 40, REG_ACC = 41, REG_GOAL_POSITION = 42,
    REG_GOAL_TIME = 44, REG_GOAL_SPEED = 46, REG_TORQUE_LIMIT = 48, REG_LOCK = 55,
    REG_PRESENT_POSITION = 56, REG_PRESENT_SPEED = 58, REG_PRESENT_LOAD = 60, REG_PRESENT_VOLTAGE = 62,
    REG_PRESENT_TEMPERATURE = 63, REG_MOVING = 66, REG_PRESENT_CURRENT = 69;
  enum class Mode : uint8_t { POSITION = 0, WHEEL = 1, PWM = 2, STEP = 3 };
  static constexpr size_t MAX_PACKET = 32;

  static size_t BuildPing(uint8_t id, uint8_t * out);                                   // 6 バイト
  static size_t BuildRead(uint8_t id, uint8_t reg, uint8_t len, uint8_t * out);         // 8 バイト
  static size_t BuildWrite(uint8_t id, uint8_t reg, const uint8_t * data, uint8_t len, uint8_t * out);
  static size_t ResponseLength(uint8_t data_len);  // 6 + data_len（FF FF ID LEN ERR DATA CHK）
  static uint16_t EncodeSigned(int16_t v);  // 符号付き絶対値（bit15）
  static int16_t DecodeSigned(uint16_t raw);
  static int16_t DecodeLoad(uint16_t raw);    // 負荷だけ bit10 が符号
  static void PutU16(uint16_t v, uint8_t * out);   // リトルエンディアン
  static uint16_t GetU16(const uint8_t * in);

  struct Response { uint8_t id; uint8_t error; uint8_t len; uint8_t data[16]; };
  // buf の中から FF FF を探して 1 パケット取り出す。チェックサム不一致 / 長さ不足なら false。consumed = 使ったバイト数
  static bool ParseResponse(const uint8_t * buf, size_t n, Response & out, size_t & consumed);
};

// 半二重バス 1 本。送って、期待する長さの応答を timeout_ms まで待つ。返り値 = 受けたバイト数（エコーは除く）、負はエラー。
// 実装は機体側（gamma_turret_fw が rabcl_esp32::HalfDuplexSerial を包む薄いアダプタを持つ。rabcl_esp32 は rabcl に依存しない）
class St3215Port
{
public:
  virtual ~St3215Port() = default;
  virtual int Transfer(const uint8_t * tx, size_t tx_len, uint8_t * rx, size_t rx_len, uint32_t timeout_ms) = 0;
};

struct St3215Status { int16_t position; int16_t speed; int16_t load; uint8_t voltage; uint8_t temperature; bool moving; int16_t current; };

class St3215  // サーボ 1 個
{
public:
  St3215(St3215Port & port, uint8_t id, uint32_t timeout_ms = 10);
  bool Ping();
  bool ReadU8(uint8_t reg, uint8_t & v);
  bool ReadU16(uint8_t reg, uint16_t & v);
  bool ReadS16(uint8_t reg, int16_t & v);   // DecodeSigned
  bool Read(uint8_t reg, uint8_t * data, uint8_t len);
  bool WriteU8(uint8_t reg, uint8_t v);
  bool WriteU16(uint8_t reg, uint16_t v);
  bool Write(uint8_t reg, const uint8_t * data, uint8_t len);
  bool SetMode(St3215Protocol::Mode mode);       // LOCK 0 → MODE → LOCK 1
  bool SetTorque(bool on);
  bool Move(int16_t position_or_steps, uint16_t speed, uint8_t acc);  // ACC〜GOAL_SPEED の 7 バイトを 1 回で（位置モードは絶対、ステップモードは相対）
  bool ReadStatus(St3215Status & out);           // 56〜70 の 15 バイトを 1 回の READ で
  uint8_t last_error() const;                    // 応答の ERR
  uint32_t timeouts() const;                     // 応答なしの回数
};
}
```

### 4.2 rabcl_esp32 `HalfDuplexSerial`（設計書 2026-10-20 の「後回し」を実装）

```cpp
struct HalfDuplexSerialConfig { uart_port_t port; int tx; int rx; int baud; int rx_buffer; };
class HalfDuplexSerial  // rabcl に依存しない（rabcl_esp32 の方針）。St3215Port への適合は gamma_turret_fw 側のアダプタ
{
public:
  explicit HalfDuplexSerial(const HalfDuplexSerialConfig & config);
  esp_err_t Start();
  int Transfer(const uint8_t * tx, size_t tx_len, uint8_t * rx, size_t rx_len, uint32_t timeout_ms);
};
```

`Transfer`: 受信バッファを捨てる → 送信 → `uart_wait_tx_done` → **tx_len バイトのエコーを読み捨てる**（timeout 内に揃わなければ −1）→ rx_len バイトを timeout まで読む（`uart_read_bytes` はタイムアウトまで揃うのを待つ。足りなければ読めた数を返す）。1 Mbps なら 8 バイトの送受で約 0.2 ms、サーボの応答遅れは既定 0 なので timeout 10 ms で十分。

### 4.3 gamma_turret_fw の試験モード

- `platformio.ini` に `[env:st3215_test]`（`stamp_p4` を継承、`build_flags = -DGAMMA_ST3215_TEST`）。`src/main.cpp` の `app_main` を `#ifndef GAMMA_ST3215_TEST` で囲い、`src/st3215_test.cpp` が `#ifdef GAMMA_ST3215_TEST` の `app_main` を持つ。制御本体（CAN、IMU）は起動しない。
- `board.hpp` に `SERVO_UART_PORT = UART_NUM_1`、`SERVO_UART_TX_PIN = 8`、`SERVO_UART_RX_PIN = 10`、`SERVO_UART_BAUD = 1000000`。`src/servo_bus.hpp` に `rabcl::St3215Port` を `HalfDuplexSerial` で実装する数行のアダプタ。
- USB-Serial-JTAG のコンソールから 1 行コマンド（`pio device monitor` で打つ）:

| コマンド | 動き |
|---|---|
| `i` | Ping、レジスタ 3〜70 を読んで表示（モデル、ID、ボーレート、角度制限、モード、トルク、現在位置など） |
| `m <0-3>` | モード変更（LOCK 0 → MODE → LOCK 1）。確認のため読み戻す |
| `t <0/1>` | トルク OFF / ON |
| `s <steps> [speed] [acc]` | ステップ（または位置モードなら絶対位置）を 1 回。送ってから 2 ms ごとに位置と Moving を読み、Moving が 0 に戻るまでの時間、最終位置、行き過ぎ（最大位置 − 最終位置）を表示。タイムアウト 2 s |
| `l <n> <steps> <period_ms>` | `s` を period_ms 周期で n 回（steps は整数固定）。各回の所要時間（Moving 1 → 0）と、累積の位置ずれ（期待 n × steps との差）を表示。項目 3 の検証。170.67 カウントの割り振り（Bresenham）は装填の本設計で扱う |
| `p [ms]` | 現在位置・速度・負荷・電圧・温度・Moving を ms 周期で流し続ける（Enter で止める）。トルク OFF で手で回して多回転の巻き戻りを見る（項目 1） |
| `w <reg> <val>` / `r <reg> [len]` | 生のレジスタ読み書き（調査用） |

- ログは `ESP_LOGI` に加えて `s` / `l` の結果を 1 行の表形式（`step=+171 t_move=57ms pos 100→271 overshoot=2`）で出す。コピーして設計メモに貼れる形。

## 5. テスト

- rabcl `test/test_st3215.cpp`（gtest、fake の `St3215Port` が送信を記録し、用意した応答を返す）:
  - `BuildPing` = `FF FF 01 02 01 FB`、`BuildRead(1, 56, 2)` = `FF FF 01 04 02 38 02 BE`、`BuildWrite(1, 42, {0xAB, 0x00}, 2)` のチェックサム。
  - `EncodeSigned(−100)` = 0x8064、`DecodeSigned(0x8064)` = −100、`EncodeSigned(171)` = 171、`PutU16` / `GetU16` がリトルエンディアン。
  - `ParseResponse`: 正常、先頭にごみ 3 バイト、チェックサム不一致、長さ不足（false）。
  - `St3215::Move(171, 1000, 50)` が 41 番地から `32 AB 00 00 00 E8 03` を書く（ACC 50、位置 171、時間 0、速度 1000）、負のステップは bit15。
  - `ReadStatus` が 15 バイトの応答を各フィールドに分け、position / speed / current の負値（bit15）と load の負値（bit10）を復号する。
  - 応答なし（Transfer が 0）で false + timeouts が増える。ERR ≠ 0 で `last_error` に残る。
- rabcl_esp32: `HalfDuplexSerial` は fake の UART で「エコーを読み捨ててから応答を読む」を確かめる（既存の `SerialPort` テストと同じ流儀で、`uart_*` を差し替える）。rabcl への依存は足さない。
- 進め方: rabcl → rabcl_esp32 → gamma_turret_fw の順。rabcl と rabcl_esp32 はコミット・push（承認後）してから、ファームの submodule を進める。
- 実機は 6 章の手順。

## 6. 実機の検証手順（設計メモ 5.1 の 4 項目）

0. 配線と電源: SRV1 に ST3215、安定化電源 7.4V / 2 A 制限、P4 は USB。`i` で Ping が通り、モデル・ID 1・ボーレート 0（1 Mbps）・モードが読めること。電圧レジスタが 7.4V 付近（単位 0.1V）。
1. 多回転: `t 0` → `p 50` で手で 2 回転以上回し、現在位置が 4095 → 0 に巻き戻るか、連続して増え続けるか（ステップモードと位置モードで両方）。±32768 まで回せるなら巻き戻りの挙動。
2. 到達判定: `m 3` → `t 1` → `s 171 1000 50` を数回。Moving が 1 → 0 になる時刻と、位置が目標の ±5 カウント内に入る時刻の差。到達の判定に Moving を使えるか、位置読みで十分か。
3. 所要時間: `l 20 171 100` で 100 ms 周期の 20 回。各回の t_move が 100 ms 未満か、累積ずれが ±5 カウント内か。速度 / 加速度を変えて 3 条件（例: speed 1000 / 2000 / 3000、acc 50 / 100 / 150）。
4. 負方向: `s -171 1000 50` と `s -342` で逆転が同じ時間で済むか、行き過ぎが同程度か。

結果は設計メモ 5.1 に追記し、装填の本設計（次の設計書）の入力にする。
